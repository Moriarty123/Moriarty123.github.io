# 卡片页面容器全屏

一个 Vue 3 + Vite 的图表卡片页：8 张卡片两列排布，每张内嵌一个 ECharts 图表，点右上角按钮可让卡片在容器内铺满 / 还原。

> 完整源码见[第九节](#九完整源码)。

## 一、文件结构

| 文件 | 职责 |
| --- | --- |
| `src/App.vue` | 页面主体：卡片数据、行容器 + 卡片结构、全部样式、展开状态消费 |
| `src/components/EChart.vue` | ECharts 通用封装：按需注册、初始化、尺寸自适应、销毁 |
| `src/chart-options.js` | 8 套 ECharts option，按 key 取用 |
| `src/composables/useExpandable.js` | 展开 / 折叠的状态逻辑（可复用） |

数据流：

```
cards[].chart  →  chartOptions[key]  →  <EChart :option="..." />
                                              ↓
                                   useExpandable() 控制铺满 / 还原
```

## 二、布局：每行两个 + 页面滚动

布局用「每行一个 flex 容器」，而不是 grid：

```css
.card-container {
  display: flex;
  flex-direction: column;
  gap: 20px;   /* 行间距 */
}

.row {
  display: flex;
  gap: 20px;   /* 列间距 */
}

.card {
  flex: 1 1 0; /* 默认等分，一行两张各 50% */
  min-height: 360px;
}
```

- 数据先用 `cardRows` 计算属性按「每行两张」切成二维数组（`[[c1,c2],[c3,c4],...]`），模板里用「外层 `v-for` 行 + 内层 `v-for` 卡片」两层循环渲染。
- 每行是一个独立的 flex 容器，**卡片宽度由 `flex: 1 1 0` 等分**；`min-height: 360px`（不是 `height`，内容多时可继续被顶高，不会截断）。
- 选 flex 而非 grid 的原因：grid 想做「同一行内不同列宽」（如第三行 40/60）只能把列切到能整除的粒度（如 10 列），且 gap 会被算进每个 span，比例有约 4px 误差；flex 用 `flex: 4 / flex: 6` 即可精确 40% / 60%，gap 单独算、不参与比例。
- 8 张卡片 = 4 行 ≈ 1500px，加 `.page` 上下各 40px 内边距 ≈ 1580px，超出视口后页面自然出现纵向滚动条。
- 窄屏回退单列：把行改成纵向即可：

```css
@media (max-width: 640px) {
  .row { flex-direction: column; }
}
```

### 卡片头部的可选描述区

卡片标题下方可放一段 `desc` 描述（仅 `card.desc` 有值时渲染 `.card-desc`）。它让卡片头部高度可变，是验证「卡片内容高低不一时布局是否还稳」的关键——见第八节。

## 三、展开 / 折叠：容器内铺满（非浏览器全屏）

**没有使用** `requestFullscreen()` 等浏览器全屏 API，纯 CSS 实现。

```css
.card-container { position: relative; }        /* 定位参照 */

.card-expanded {
  position: absolute;
  inset: 0;                                     /* 铺满整个容器 */
  z-index: 2;                                   /* 盖住其余卡片 */
}
```

关键点：

1. **容器必须 `position: relative`**，否则绝对定位会向上找到 `body`，变成铺满整页。
2. 展开卡片在 DOM 里是 `.row > .card`，但 `.row` 没有设 `position`，不构成包含块；它的包含块是最近的定位祖先 `.card-container`，所以 `inset: 0` 正好等于铺满整个容器。同时卡片 `position: absolute` 脱离 flex 行流，不再占行内格子（配合下面的「其余卡片 `display: none`」一起生效）。
3. 状态用「当前展开的卡片 id」而不是布尔值，天然保证同时只展开一张：

```js
const expandedId = ref(null)
function toggle(id) {
  expandedId.value = expandedId.value === id ? null : id
}
```

## 四、展开态不出现滚动条

四处配合，缺一不可：

```css
/* 1. 页面：至少一屏高的纵向 flex */
.page {
  box-sizing: border-box;
  min-height: 100vh;
  display: flex;
  flex-direction: column;
}

/* 2. 展开时容器吃掉整屏剩余高度 */
.card-container.is-expanded { flex: 1; min-height: 0; }

/* 3. 其余卡片不参与高度计算 */
.card-container.is-expanded .card:not(.card-expanded) { display: none; }

/* 4. 全局：清掉 body 默认 8px 外边距 */
body { margin: 0; }
```

- 第 3 条是核心：其余卡片即便被遮住，只要在文档流里，容器高度仍是 ~1500px，展开卡片会被拉成一整屏列表那么高。
- 第 2 条用 `flex: 1` 而不是 `height: calc(100vh - 80px)`，避免把内边距数值写死两处。
- 第 4 条不能省：body 默认上下各 8px，总高会变成 `100vh + 16px`，刚好又冒出滚动条。因为要作用于全局，`App.vue` 里用了第二个不带 `scoped` 的 `<style>` 块。

结果：文档总高正好 100vh，展开态无滚动条；收起后内容 ~1580px，滚动条回来。

## 五、ECharts 集成

### 按需注册

```js
import * as echarts from 'echarts/core'
import { LineChart, BarChart, PieChart, RadarChart, ScatterChart, GaugeChart } from 'echarts/charts'
import { GridComponent, TooltipComponent, LegendComponent, RadarComponent } from 'echarts/components'
import { CanvasRenderer } from 'echarts/renderers'

echarts.use([/* ... */])
```

全量 `import * as echarts from 'echarts'` 会让产物从 63KB 涨到 1184KB（gzip 397KB）；按需注册后为 645KB（gzip 221KB）。**新增图表类型时记得同步 `echarts.use()` 的注册列表。**

### 生命周期

```js
onMounted(() => {
  chart = echarts.init(el.value)
  chart.setOption(props.option)

  observer = new ResizeObserver((entries) => {
    const { width, height } = entries[0].contentRect
    if (width > 0 && height > 0) chart.resize()
  })
  observer.observe(el.value)
})

onBeforeUnmount(() => {
  observer.disconnect()   // 先停监听，避免销毁后仍回调 resize
  chart.dispose()
})
```

`ResizeObserver` 一处解决三种场景：窗口缩放、卡片展开 / 收起、卡片从 `display: none` 恢复。尺寸为 0 时跳过，避免 resize 成 0。

### 使用约定

`<EChart>` 的根节点是 `position: absolute; inset: 0`，因此**父容器必须 `position: relative` 且高度由 CSS 确定**（固定值或 flex 分配均可）。

## 六、踩坑：画布反向撑高父容器

**现象**：展开再收起后，卡片和它同行的另一张都永久变高了。

**原因**：ECharts 会给内部容器写死像素高度。展开时图表 resize 到约 700px，而卡片高度是 `min-height: 360px` 由内容决定，`.card-chart` 是 `flex: 1` —— **父容器高度不确定时，`flex: 1` 子项的内容会参与父容器高度计算**，形成死循环：

```
卡片被画布撑到 760px
  → 收起时卡片回不到 360px（内容还占着 700px）
  → .echart 尺寸没变化 → ResizeObserver 不触发
  → 图表永不缩回 → 卡片永久变高
  → 同行卡片因 align-items: stretch 跟着变高
```

**修法**：让图表区脱离文档流，切断尺寸回流。

```css
/* 父容器 */
.card-chart { position: relative; flex: 1; min-height: 0; overflow: hidden; }

/* EChart 根节点 */
.echart { position: absolute; inset: 0; }
```

高度变成单向流动：卡片 360px → `.card-chart` 拿到确定的 274px → 图表跟随。

> 注意：`flex: 1 + min-height: 0` 只解决「父容器高度确定时子项能收缩」，**解决不了「父容器高度不确定时内容反向撑高父容器」**。图表 / 画布这类自带像素尺寸的内容放进 `flex: 1` 区域，一律建议用「父 `relative` + 子 `absolute inset: 0`」。

## 七、状态逻辑复用

`src/composables/useExpandable.js`：

```js
export function useExpandable() {
  const expandedId = ref(null)
  const isAnyExpanded = computed(() => expandedId.value !== null)
  const isExpanded = (id) => expandedId.value === id
  function toggle(id) {
    expandedId.value = expandedId.value === id ? null : id
  }
  return { expandedId, isAnyExpanded, isExpanded, toggle }
}
```

在新页面复用的三步：

1. `const { isAnyExpanded, isExpanded, toggle } = useExpandable()`
2. 容器 `:class="{ 'is-expanded': isAnyExpanded }"`，卡片 `:class="{ 'card-expanded': isExpanded(id) }"`
3. 复制第四节那几条配套样式（它们是样式契约）

隐含依赖：`.card-container.is-expanded { flex: 1 }` 要求外层是 `min-height: 100vh` 的纵向 flex。若新页面结构不同，改用 `height: calc(100vh - 页面上下内边距)` 效果相同。

## 八、已知限制与扩展方向

- **展开 / 收起是瞬时的**：`position` 在 `static` ↔ `absolute` 之间切换无法用 `transition` 过渡。要做动画有两条路：
  - View Transitions API（最省事）：`document.startViewTransition(async () => { toggle(id); await nextTick() })`，配合每张卡片唯一的 `view-transition-name`，十几行搞定，老浏览器自动降级为瞬时切换。
  - FLIP：切换前后各测一次 `getBoundingClientRect()`，用 Web Animations API 补间 `transform` + `width` / `height`。要注意此时卡片不能是 `display: none`，否则测量全是 0。
- **`display: none` 的影响**：元素不生成布局盒，`getBoundingClientRect()` 全 0，不进无障碍树；但 Vue 组件不销毁、DOM 节点和状态都保留，图片也仍会下载。卡片里若放需要容器尺寸的库（如 ECharts），当前的 `ResizeObserver` 方案已能自动恢复。
- **卡片内容高低不一不会错位**：同一行是 flex，默认 `align-items: stretch`，两张卡等高取较高者；较矮那张的 `.card-chart`（`flex: 1`）自动撑大吸收差值，图表经 `ResizeObserver` 重绘不变形，`min-height: 360px` 兜底下限。已用「第 0 行左卡长描述 / 右卡无描述、第 1 行左右各一段不等长描述」验证通过：构建无报错、图表不拉伸、行内始终对齐。唯一限制是「行内等高、行与行可不等高」——若要求 8 张全部严格齐平，需把行高锁死（固定行高 + `overflow` 处理超长内容）。
- **产物体积**：Vite 会提示 chunk > 500KB，是因为同时用到了 6 种图表类型。继续瘦身可删掉 `echarts.use()` 中没用到的类型。
- **`defineProps` 是编译宏**：只在 `<script setup>` 中由编译器注入，普通 `<script>` 块里不可用，也不能从 `'vue'` 导入。普通 `<script>` 里要声明 props，请改用 `export default { props: {...}, setup(props) {...} }`。

### `src/components/EChart.vue`

```vue
<script setup>
import { ref, watch, onMounted, onBeforeUnmount } from 'vue'
import * as echarts from 'echarts/core'
import {
  LineChart,
  BarChart,
  PieChart,
  RadarChart,
  ScatterChart,
  GaugeChart,
} from 'echarts/charts'
import {
  GridComponent,
  TooltipComponent,
  LegendComponent,
  RadarComponent,
} from 'echarts/components'
import { CanvasRenderer } from 'echarts/renderers'

// 按需注册：只打包用到的图表和组件（全量引入会让产物增加约 900KB）
echarts.use([
  LineChart,
  BarChart,
  PieChart,
  RadarChart,
  ScatterChart,
  GaugeChart,
  GridComponent,
  TooltipComponent,
  LegendComponent,
  RadarComponent,
  CanvasRenderer,
])

const props = defineProps({
  // 标准 ECharts option
  option: { type: Object, required: true },
})

const el = ref(null)
let chart = null
let observer = null

onMounted(() => {
  chart = echarts.init(el.value)
  chart.setOption(props.option)

  // 容器尺寸变化时才 resize：窗口缩放、卡片展开/收起、display:none 恢复都会触发
  observer = new ResizeObserver((entries) => {
    const { width, height } = entries[0].contentRect
    if (width > 0 && height > 0) chart.resize()
  })
  observer.observe(el.value)
})

// option 整体替换时重绘（换数据源用）
watch(
  () => props.option,
  (option) => chart && chart.setOption(option, true)
)

onBeforeUnmount(() => {
  // 先停监听再销毁实例，避免销毁后仍回调 resize
  if (observer) {
    observer.disconnect()
    observer = null
  }
  if (chart) {
    chart.dispose()
    chart = null
  }
})
</script>

<template>
  <div ref="el" class="echart"></div>
</template>

<style scoped>
/*
 * 绝对定位是关键：ECharts 会给内部容器写死像素宽高，
 * 若这里是普通流内元素，画布高度会反过来撑高父容器，
 * 导致「容器无法缩回 → ResizeObserver 不触发 → 图表不缩回」的死循环。
 * 因此要求父容器 position: relative 且高度由 CSS（固定值或 flex）确定。
 */
.echart {
  position: absolute;
  inset: 0;
}
</style>
```

### `src/composables/useExpandable.js`

```js
import { ref, computed } from 'vue'

/**
 * 卡片「展开占满容器」的状态逻辑
 * 注意：这是纯状态，配套样式由各页面自己维护（容器 .is-expanded、卡片 .card-expanded 等）
 * @returns {{ expandedId: import('vue').Ref<number|string|null>, isAnyExpanded: import('vue').ComputedRef<boolean>, isExpanded: (id: number|string) => boolean, toggle: (id: number|string) => void }}
 */
export function useExpandable() {
  // 存 id 而不是布尔值：天然保证同时只展开一张，切换时上一张自动收起
  const expandedId = ref(null)

  // 是否有卡片处于展开态，用于给容器加类（撑高容器）
  const isAnyExpanded = computed(() => expandedId.value !== null)
  const isExpanded = (id) => expandedId.value === id

  // 再次点击同一张则收起
  function toggle(id) {
    expandedId.value = expandedId.value === id ? null : id
  }

  return { expandedId, isAnyExpanded, isExpanded, toggle }
}
```
